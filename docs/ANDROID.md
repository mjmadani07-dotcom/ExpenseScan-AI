# Android implementation roadmap

Phase 0 initializes the branch and baseline. Current status: implementation starts here; APK generation and device acceptance remain future work. Track acceptance by evidence, not by documentation alone.

| Phase | Deliverable | Acceptance gate |
| --- | --- | --- |
| 0 | branch, architecture, baseline package/lock/scripts, ignore rules, CI checks | clean install, lint, tests, web build and production health smoke pass |
| 1 | domain validation, exact amounts, local date, seed separation | invalid data rejected, Jalali leap/boundary and currency/instalment regression tests pass |
| 2 | repository interfaces, SQLite, migrations, attachments/drafts and JSON import | offline CRUD survives relaunch; transactional failure leaves previous data intact; no Express dependency in native mode |
| 3 | Capacitor native Android shell, camera, document picker, sharing, lifecycle and back | install debug APK; launch airplane-mode; camera/PDF and permission denial handled |
| 4 | lock, credential storage, backups, restore, audit/soft deletion | recovery on second device; no leaked secrets; failed migration/restore preserves data |
| 5 | mobile UX, settings-only AI panel, condensed forms, draft persistence, numeric inputs | small-screen and RTL tests, hardware back, Persian digits, accessibility |
| 6 | lazy imports, local fonts, page/attachment limits and pagination | performance measured on representative device; offline font and large ledger work |
| 7 | signed release workflow, release notes and upgrades | repeatable APK build; same signer and application ID; monotonically increasing versionCode |
| 8 | device acceptance | clean install, offline/online workflows, interrupted saves, update with existing data and restore verified |

## Build and distribution policy

Use a dedicated Android CI workflow after native project exists. Test/lint/build on changes; avoid persistent test artifacts. Keep debug APK artifacts at 1–3 days only when useful, release APKs on explicit tags/releases. Do not delete published versions or signing material automatically. No production credentials in debug builds. Choose final application ID, supported Android API level, Capacitor/SQLite plugin versions and signing identity in phase 3 after verifying compatibility. Do not publish release until phase 8 gates pass.

## Current baseline

The external review reported passing type checking/tests/build; not independently reproduced at planning time. CI is intended to verify branch changes. The npm/esbuild conflict is evidenced by direct esbuild ^0.25 versus Vite peer ^0.27 or ^0.28; remove the unnecessary direct dependency and align lock to the existing tsx transitive resolution. The existing web server still contains known security/data issues and is for local development only. No native project or APK at phase 0.

## Phase 1 changes
Global display unit is independent of source currency; domestic amount inputs convert reversibly, foreign amount entry stays explicitly denominated in the original currency with equivalent display. Tehran business date is default; event timestamps stay UTC. Added shared validation for new/edited expenses, empty operational store and fail-closed legacy JSON read. Import validation and full durable offline storage still require further work. CI and device UX validation are required.

## Phase 2 — first storage milestone
The application now receives a LedgerRepository, with HTTP web and local SQLite implementations. Shared LedgerDomain is used by the existing server and the local repository. SQLite schema v1 intentionally stores a versioned ledger/draft snapshot in one row with compare-and-swap commits, atomic draft approval and explicit errors; Node SQLite integration tests exercise persistence and conflicts. The local repository is wired to draft restore/save/approval in App via dependency injection; the Android native driver, device validation of draft lifecycle, normalization into per-entity tables, encrypted attachments/backups, and device acceptance are still pending. No APK yet. The default entry point still uses web mode until a native driver is installed.

## Phase 3 experimental native shell
The separate native toolchain pins Capacitor 7.4.5 (Android SDK 35/JDK 21). The Android app ID is ir.expensescan.hesabyar, with a generated platform scaffold plus checked-in Java overlay. The native bridge provides only initialize/read/compare-and-swap/minimize, backed by Android private SQLite. The bundled build fails closed if the bridge is missing, never falls back to HTTP or localStorage for finance. Hardware back returns from selected record/tab, or minimizes at overview. Existing HTML camera/file inputs are supported by the Capacitor WebView but require device testing. Android cloud backup disabled. The CI debug APK is experimental, retained one day, may use a different debug signing key per runner; do not enter real information or rely on in-place upgrades before release signing, backup and security are complete. Native dependencies are separately pinned at top level; full transitive lock and stable signing are pending. Native source and build script are in native/android and scripts/prepare-android.mjs. No production API key is bundled; AI direct client mode still requires security review and user supplied credentials. Test on current Android System WebView. No device test claimed by successful build alone.

## Phase 4 security milestone
Native schema v2 encrypts the snapshot payload with an AES-256-GCM Android Keystore key; v1 migration is transactional. The separate API vault uses a different Keystore key. Portable encrypted backup uses PBKDF2-SHA256 (600,000 iterations) and AES-GCM; Android Storage Access Framework exports a user-selected file. One rotating recovery checkpoint is committed atomically before destructive ledger operations. Restore previews require confirmation. Portable backups exclude AI configuration and credentials, include existing draft/preview data only. Device lock, original attachments, stable release signing and on-device migration/restore testing remain pending. A v1 upgrade does not guarantee old plaintext pages are securely erased. Do not use real financial data before acceptance.

## Stable signing preparation
An explicit-tag-only signed beta workflow is provided. Owner-controlled environment secrets and certificate fingerprint are required; no release key has been generated and no signed beta has been built. See [ANDROID_SIGNING.md](ANDROID_SIGNING.md).

## Phase 4: device credential gate and file export
Android now requires a secure device screen lock and explicit system credential confirmation on each app process start. Native session checks reject storage/vault/export calls when locked or expired; five minutes idle or 30 seconds stopped, explicit lock and FLAG_SECURE (screenshots/recent task protection). The native file chooser may expire the session during lengthy selection; retry after unlock. No custom PIN or biometric-specific prompt yet. Native JSON/XLSX use Storage Access Framework; these are intentionally plaintext exports, not encrypted backups. Test on real Android, including background transitions and file picker cancellation. No migration claim beyond CI compilation.

Recovery archive now retains three newest snapshots (manual or automatic), with explicit selected restore/delete and migration of the legacy single checkpoint. On restoring, the current state is saved as a new checkpoint. Oldest is automatically pruned; the existing native 32 MiB snapshot limit still applies to the entire archive. An oversized write fails rather than silently deleting additional backups. External encrypted backups remain essential. Multi-version snapshots are transitional; per-entity tables and attachment files remain pending.

Native exports normalize Persian date digits in the filename for the Android bridge. Short file chooser transitions do not invalidate the session simply because the activity is momentarily stopped; the 30-second background and five-minute idle thresholds still apply.

Original attachments are immutable SHA-256-addressed encrypted files in Android private storage, separate from ledger snapshots. PDF/image/text files up to 12 MiB each may be attached during AI extraction or manual capture; a small thumbnail only is retained for new native AI drafts. File export requires explicit confirmation and produces plaintext in the chosen destination. Portable encrypted backups include and verify every referenced original, restore files before atomic ledger replacement, and reject incomplete/oversized backups. JSON sync excludes original references; merge retains existing local references by ID. Unreferenced encrypted files are retained deliberately to protect recovery checkpoints; garbage collection and streaming multi-file backup are pending. Device test required.

The app exports an original through the Android file chooser for viewing in a compatible app; it does not yet include an integrated full PDF viewer. New native draft review shows only a thumbnail; all original bytes are preserved separately. The debug APK workflow includes attachment-related UI and storage changes as build triggers.

## Native schema 3
Native finance data now lives in encrypted per-entity tables with FK-checked line items/tranches and atomic revision-checked row patches. Migration validates and round-trips legacy state before the native transaction creates rows and drops the old table. The 32 MiB former whole-ledger write cap is replaced by a 32 MiB per-row limit and a 64 MiB patch limit; the JS bridge still materializes the full ledger, and recovery rows/portable backups remain limited. No claim of unlimited capacity or on-device migration verification. See DATA_MODEL.md.

Settings → Backup → Attachment storage audit reports referenced, missing and unreferenced originals and actual encrypted bytes. This is deliberately read-only pending race-safe cleanup and on-device verification. A missing-file count tests file presence, not full cryptographic integrity; read/export still verifies the digest.

## Mobile-first refinement
Manual/offline entry is prominent, advanced AI controls collapse by default in Android, PDF selection preserves original immediately without rendering until AI extraction, and PDF AI extraction explicitly rejects documents longer than its ten-page analysis limit rather than silently omitting pages. Review provides a sticky confirm action and collapsible payment/line-item details. Ledger list renders 30 results per page; full filtered counts, totals and export remain unchanged. Settings can test actual model extraction using only synthetic data (may incur provider charges); HTTPS required on Android, redirects blocked, and remote response bodies are not displayed. Fontsource Vazirmatn 5.2.8 (OFL) is copied at packaging time with its license; Google Fonts links are removed from Android assets. Build and real-device acceptance remain required. Web retains its existing online font setup. CORS and provider reachability still depend on the user's network/provider.

Android authentication now offers AndroidX BiometricPrompt 1.1.0 for enrolled BIOMETRIC_STRONG authenticators, with separate system PIN/pattern/password login as fallback. No biometric templates or PIN are stored by the app. Existing five-minute idle and 30-second stopped session boundaries apply. Biometric hardware, cancellation, lockout, background and upgrade cases require physical-device testing. Capacitor loggingBehavior is explicitly none.

Manual orphan cleanup now uses a native authoritative reference scan of current encrypted rows, recovery checkpoints, active drafts and approval replay records in a revision-checked transaction. It refuses cleanup if any referenced file is missing, never deletes recent files (24-hour grace) or .bak/.new sidecars, and returns actual successful removals, released bytes and failed/skipped counts. New row commits check referenced files exist; repeated attachment writes renew the grace period. No automatic deletion, no secure physical erasure claim. Device tests of interrupted capture, cleanup and restore remain required.

Debug APK CI now runs native JVM regression tests for attachment reference extraction (live, draft, recovery and replay rows), invalid data and 24-hour cleanup eligibility before assembly. These are JVM tests, not Android device or Keystore tests.

## Streaming portable backup v2
Default Android export is `.esbackup2`: binary header, password-derived AES-256-GCM key (PBKDF2-SHA256 600k), encrypted financial manifest, one authenticated frame per deduplicated original, authenticated empty terminator, exact EOF. Nonces use random prefix + sequential frame number; AAD binds header, sequence and length. Native cache staging stores only encrypted bytes; bridge appends <=1 MiB chunks, then SAF copies in 64 KiB buffers. Legacy `.esbackup` restore remains supported. v2 limits: 512 MiB total, 32 MiB financial manifest, 12 MiB each original, 10,000 attachments. Memory is bounded by manifest and one attachment, not total attachment volume; ledger itself is still read in full. Import previews authenticated manifest then verifies each attachment digest and final terminator before replacing ledger. Failure may leave encrypted unreferenced files, never a partial ledger replacement. Destination copy interruption may leave an invalid encrypted partial file; delete it and retry. Staging requires free space and is discarded on finish/error or next export. Real device storage/picker/session and large archives need verification.

Large archive regression uses four generated 9 MiB attachments written to a real temporary archive (>32 MiB), then reads them individually. Native bridge regression checks <=1 MiB chunks and cleanup on producer failure. User can cancel between attachment frames; cancellation during Android's file picker uses the system picker. Base64 decoding avoids large intermediate per-character arrays.

SAF destination copy runs on a separate native worker thread with session checks per 64 KiB chunk; staging remains reserved during the copy. A blocked provider can still delay completion, and copy interruption may leave an invalid encrypted partial file. No UI-thread copy of the complete archive.

## Active ledger projection
Android normal startup/reload and portable export read only active ledger/draft tables; recovery and approval row ciphertext is not fetched or decrypted for this scope. App loads ledger and draft together from one committed revision. Partial results cannot seed the full mutation baseline. Writes, recovery, cleanup still use complete state; all active expenses are still materialized for dashboard/filter/export. This is selective table reading, not SQL pagination or an on-device performance benchmark. A 3,000-document synthetic regression covers ordering, sum and selective row updates.

## Private attachment viewer
Android expense detail and draft review can open original PDF, supported images, CSV/text in the app, after SHA-256 verification. PDF uses bundled PDF.js worker, one page/canvas at a time, next/previous and zoom. Canvas is bounded (4 million pixels, longest edge 2400 pixels); no external PDF links, scripting or annotations rendered, and XFA disabled. Text preview is plain escaped text, first 256 KiB. Images use a revoked in-memory object URL; no plaintext temporary export. Unsupported/corrupt/password-protected files show an error; original explicit export remains available. App lock unmounts the viewer. Device tests needed, including Persian PDFs, cancellation and repeated opening.

## Android emulator smoke (separate CI)
A separate Android 35 emulator workflow starts an installed offline debug app, checks the native FLAG_SECURE lock screen, and exercises real Android SQLite + a disposable test AndroidKeyStore alias, v2-to-v3 migration, rollback, scoped reads and database reopen. Triggered only on instrumentation-test/workflow changes (or manual dispatch if available); no build artifacts uploaded. The test uses synthetic fixtures, not a deployed ledger; biometric sensor, document capture/preview, SAF backup and physical-device upgrade remain acceptance tests. The signed workflow now sets beta versionName and runs native JVM tests before signing.

## Release hardening: approval replay
Local approval is serialized and commits the ledger and draft removal together. On the latest already-committed draft ID, retries resolve current records by stable ID and creation/approval timestamps rather than returning stored copies. Missing/deleted/replaced records or mismatched count fail closed. UI ignores repeated submit events, does not re-save an already-approved draft, and reloads the committed ledger after success. This is last-approval replay protection, not global deduplication of separately created drafts. Tests cover lost acknowledgement, concurrent retries, edited values and deletion.

Beta release hardening uses docs/ANDROID_RELEASE_CHECKLIST.md to trigger candidate APK/emulator checks without generating unnecessary emulator artifacts. Signed release requires successful checks on the exact android commit, increasing versionCode, and v2/v3 certificate verification. Physical-device acceptance and owner signing setup are separate requirements.
